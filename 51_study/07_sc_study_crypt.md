# SC試験対策：暗号技術まとめ

## 1. 暗号方式の分類

| 分類 | 特徴 | 主な用途 | 代表例 |
|---|---|---|---|
| 共通鍵暗号方式 | 暗号化と復号に同じ鍵を使う | 大量データの暗号化 | AES、Camellia、3DES |
| 公開鍵暗号方式 | 公開鍵と秘密鍵のペアを使う | 暗号化、鍵共有、電子署名 | RSA、ECDH、ECDSA |
| ハッシュ関数 | データから固定長のハッシュ値を生成する | 改ざん検知、電子署名、パスワード管理 | SHA-256、SHA-384、SHA-512 |

---

## 2. 共通鍵暗号方式

暗号化と復号に同じ鍵を使用する方式。

- 処理が高速で、大量のデータの暗号化に向いている。
- 通信相手と事前に安全に鍵を共有する必要がある。
- 公開鍵暗号方式と比較して処理負荷が小さい。

| 暗号方式 | 鍵長 | ブロック長 | 特徴 | CRYPTREC |
|---|---:|---:|---|---|
| AES | 128 / 192 / 256ビット | 128ビット | 現在の代表的な共通鍵暗号 | 電子政府推奨 |
| Camellia | 128 / 192 / 256ビット | 128ビット | NTT・三菱電機が開発 | 電子政府推奨 |
| DES | 56ビット | 64ビット | 古い暗号。総当たり攻撃に弱い | 非推奨 |
| 3DES | 112ビット相当（3鍵） | 64ビット | DESを3回適用する | 運用監視 |
| ChaCha20 | 256ビット | ストリーム暗号 | ソフトウェア実装に向く高速なストリーム暗号 | 認証暗号としての利用に関連 |

### AESの特徴

- ブロック暗号方式。
- ブロック長は128ビット固定。
- 鍵長は128・192・256ビットから選択。
- 共通鍵暗号方式。
- TLSなどの通信暗号化にも利用される。

### DESと3DES

| 項目 | DES | 3DES |
|---|---|---|
| 鍵長 | 56ビット | 3鍵の場合、実効112ビット相当 |
| ブロック長 | 64ビット | 64ビット |
| 特徴 | 総当たり攻撃に弱い | DESを3回適用 |
| 現在の扱い | 安全性不足 | 新規利用には不適切 |

---

## 3. 公開鍵暗号方式

公開鍵と秘密鍵のペアを使用する方式。

| 暗号方式 | 用途 | 安全性の根拠 | 特徴 |
|---|---|---|---|
| RSA | 暗号化・電子署名 | 素因数分解問題 | 大きな合成数の素因数分解の困難性を利用 |
| DH | 鍵共有 | 離散対数問題 | 通信相手と共通鍵を共有 |
| DSA | 電子署名 | 離散対数問題 | 電子署名専用 |
| ECDH | 鍵共有 | 楕円曲線上の離散対数問題 | DHを楕円曲線暗号に応用 |
| ECDSA | 電子署名 | 楕円曲線上の離散対数問題 | DSAを楕円曲線暗号に応用 |
| EdDSA | 電子署名 | 楕円曲線上の離散対数問題 | Ed25519などが代表例 |

### 代表的な鍵長

| 方式 | 代表的な鍵長 | 備考 |
|---|---:|---|
| RSA | 2048 / 3072ビット以上 | 安全性に応じて選択 |
| DH | 2048ビット以上 | パラメータに依存 |
| ECDH | 256ビットなど | 使用する楕円曲線に依存 |
| ECDSA | 256ビットなど | 使用する楕円曲線に依存 |
| EdDSA | 方式・曲線による | Ed25519は256ビットの曲線を使用 |

※鍵長だけで安全性が決まるわけではなく、アルゴリズムやパラメータにも依存する。

### RSA：素因数分解問題

- 大きな整数を2つの素数の積として生成する。
- 素数同士の掛け算は簡単。
- 大きな合成数から元の素数を求めることは非常に困難。
- この素因数分解の困難性を安全性の根拠としている。

例：

```text
N = p × q

p、q：大きな素数
N：公開情報として利用される合成数
```

### DH：離散対数問題

- Diffie-Hellman鍵共有方式。
- 通信相手と共通鍵を安全に共有する。
- 離散対数問題の困難性を利用する。
- 暗号化方式や電子署名方式ではなく、鍵共有方式。

### 楕円曲線暗号（ECC）

| アルゴリズム | 用途 | 覚え方 |
|---|---|---|
| ECDH | 鍵共有 | DHの楕円曲線版 |
| ECDSA | 電子署名 | DSAの楕円曲線版 |
| EdDSA | 電子署名 | Ed25519などの署名方式 |

- RSAと比較して、短い鍵長で同程度の安全性を実現できる。
- 例えばRSA 3072ビットとECC 256ビットは、おおむね同程度の安全性の目安。
- 量子コンピュータのShorのアルゴリズムに対して脆弱。

## 4. ハッシュ関数

データから固定長のハッシュ値を生成する関数。

- 一方向性がある。
- 入力データの長さに関係なく、固定長のハッシュ値を出力する。
- ハッシュ値から元のデータを復元することは困難。
- 暗号化・復号を行うものではない。

| ハッシュ関数 | 出力長 | 特徴 | CRYPTREC |
|---|---:|---|---|
| MD5 | 128ビット | 衝突耐性に問題がある | 非推奨 |
| SHA-1 | 160ビット | 衝突攻撃に弱い | 運用監視 |
| SHA-256 | 256ビット | SHA-2ファミリーの代表 | 電子政府推奨 |
| SHA-384 | 384ビット | SHA-2ファミリー | 電子政府推奨 |
| SHA-512 | 512ビット | SHA-2ファミリー | 電子政府推奨 |
| SHA3-256 | 256ビット | SHA-3ファミリー | 電子政府推奨 |

### ハッシュ関数の安全性

| 用語 | 意味 |
|---|---|
| 原像計算困難性 | ハッシュ値から元の入力を求めることが困難 |
| 第二原像計算困難性 | ある入力と同じハッシュ値になる別の入力を見つけることが困難 |
| 衝突発見困難性 | 同じハッシュ値になる異なる2つの入力を見つけることが困難 |

### ハッシュ関数の用途

| 用途 | 説明 |
|---|---|
| 改ざん検知 | データのハッシュ値を比較する |
| 電子署名 | データのハッシュ値を署名対象にする |
| パスワード管理 | パスワードをハッシュ化して保存する |
| HMAC | ハッシュ関数と秘密鍵を組み合わせてメッセージ認証を行う |

※パスワード保存には、通常のSHA-256を単独で使用するのではなく、Argon2、scrypt、bcrypt、PBKDF2などのパスワードハッシュ方式を利用する。

## 5. 暗号利用モード

AESなどのブロック暗号を、複数のブロックに適用する方法。

| モード | 特徴 | 注意点 |
|---|---|---|
| ECB | ブロックごとに独立して暗号化 | 同じ平文ブロックが同じ暗号文になるため、パターンが漏れる |
| CBC | 前の暗号文ブロックと組み合わせて暗号化 | IVが必要。単独では改ざん検知できない |
| CTR | カウンタ値を暗号化して平文とXORする | カウンタの再利用は危険 |
| GCM | 暗号化と認証を同時に行う | 暗号化と改ざん検知が可能 |
| CFB | ブロック暗号をストリーム暗号のように利用 | IVが必要 |
| OFB | 暗号化結果から鍵ストリームを生成 | IVの再利用は危険 |

### 特に重要なGCM

- GCMは認証付き暗号（AEAD）。
- 暗号化だけでなく、改ざん検知もできる。
- AES-GCMはTLSなどで利用される。

## 7. CRYPTREC暗号リスト

CRYPTRECは、日本政府が電子政府などで使用する暗号技術を評価・推奨する仕組み。

| リスト | 意味 |
|---|---|
| 電子政府推奨暗号リスト | 安全性・実装性能が確認され、利用が推奨される暗号技術 |
| 推奨候補暗号リスト | 将来的に推奨リストに掲載される可能性がある暗号技術 |
| 運用監視暗号リスト | 推奨すべき状態ではないが、互換性維持などのため監視対象として扱う暗号技術 |

### 代表的な暗号技術の位置付け

| 暗号技術 | 分類 | 位置付け・注意点 |
|---|---|---|
| AES | 共通鍵暗号 | 電子政府推奨 |
| Camellia | 共通鍵暗号 | 電子政府推奨 |
| RSA | 公開鍵暗号 | 用途・パラメータごとに掲載 |
| ECDSA | 電子署名 | 電子政府推奨 |
| ECDH | 鍵共有 | 電子政府推奨 |
| SHA-256 | ハッシュ関数 | 電子政府推奨 |
| SHA-384 | ハッシュ関数 | 電子政府推奨 |
| SHA-512 | ハッシュ関数 | 電子政府推奨 |
| SHA-1 | ハッシュ関数 | 運用監視 |
| 3-key 3DES | 共通鍵暗号 | 運用監視 |
| MD5 | ハッシュ関数 | 安全性不足・非推奨 |

※CRYPTRECの掲載状況はアルゴリズム名だけで一律に決まるわけではなく、用途・鍵長・パラメータなどによって異なる。試験時には最新の公式リストを確認する。

## 8. 耐量子計算機暗号（PQC）

量子コンピュータによる攻撃に耐えることを目指した暗号技術。

従来のRSAやECCは、量子コンピュータのShorのアルゴリズムによって安全性が脅かされる。

| 技術 | 用途 | 基礎となる仕組み |
|---|---|---|
| ML-KEM | 鍵カプセル化・鍵共有 | 格子問題 |
| ML-DSA | 電子署名 | 格子問題 |
| SLH-DSA | 電子署名 | ハッシュ関数 |
| AES-256 | 共通鍵暗号 | 総当たり攻撃への耐性 |
| SHA-384 / SHA-512 | ハッシュ関数 | ハッシュ関数の安全性 |

### 重要なポイント

| 従来の方式 | 量子コンピュータによる影響 |
|---|---|
| RSA | Shorのアルゴリズムで素因数分解が効率化される |
| DH | Shorのアルゴリズムで離散対数問題が効率化される |
| ECC | Shorのアルゴリズムで楕円曲線上の離散対数問題が効率化される |
| AES | Groverのアルゴリズムで総当たり探索が平方根程度に効率化される |
| SHA | Groverのアルゴリズムなどによる探索効率化の影響を受ける |

### ML-KEM

- 格子問題に基づく鍵カプセル化方式。
- 以前の名称はCRYSTALS-Kyber。
- RSAやECDHとは異なる数学的問題を利用する。
